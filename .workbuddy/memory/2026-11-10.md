## 第五轮：修复 dev 模式 fastdom 报错（仅 production build 正常而 dev 挂）
- 现象：`npm run docs:dev` 浏览器报 `The requested module '/limin-Face-Doc/node_modules/fastdom/fastdom.js?v=...' does not provide an export named 'default'`，来源 `mermaid/dist/chunks/mermaid.core/chunk-GMAD6QVW.mjs:255`
- **根因**：`vitepress-plugin-mermaid@2.0.17` 的 `withMermaid()` 硬编码 `vite.optimizeDeps.include = [...用户配置, "@braintree/sanitize-url","dayjs","debug","cytoscape-cose-bilkent","cytoscape"]` 并给 UMD 包加 ESM alias，但白名单漏了 Mermaid 11.17 新增的 `fastdom` 与 `fastdom/extensions/fastdom-promised.js`（两者都是 UMD/CJS，`module.exports`）。dev 下 Vite 未预构建它们 → 直出 UMD 源码被浏览器按 ESM 解析 → 无 default；build 由 Rollup commonjs 插件转换，所以一直正常
- **修复**（最小改动）：`config.mts` 顶层加 `vite: { optimizeDeps: { include: ["fastdom","fastdom/extensions/fastdom-promised.js"] } }`。withMermaid 用展开运算符合并 include，用户配置不会被覆盖
- 排除的错误假设：回退 Vite 5.4.21 **同样报错**（证伪「Vite 6 override 不兼容」），且 audit 回到 4 漏洞；已恢复 `vite ^6.4.6`（0 漏洞）
- 无害现象：`Failed to resolve dependency: debug` 是插件硬编码 include 了不存在的包，与 Vite 版本无关；首次抓取时的 `vitepress data not properly injected in app` 是 `optimized dependencies changed. reloading` 的瞬时错误，二次刷新即消失
- 验证：预构建产物 `fastdom.js` / `fastdom_extensions_fastdom-promised__js.js` 生成；Chrome headless console 零错误、DOM 有 `<svg class="flowchart">`；build 17.77s、366 条链接 0 失效、0 漏洞、123 张图 / 50 页渲染
- 环境坑：npm install 报 `ENOTEMPTY rename node_modules/vite` 时，把残留 `node_modules/.vite-XXXX` 目录 mv 到 /tmp 再装；WorkBuddy safe-delete shim 会拦 Vite 清理 >50 个缓存文件导致 dev server 崩溃，先把 `.vitepress/cache` mv 到 /tmp（移动而非删除）
