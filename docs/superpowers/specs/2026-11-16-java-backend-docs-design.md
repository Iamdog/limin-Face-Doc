# Java 后端文档信息架构设计

## 意图

把 Java 后端文档从“按文章堆叠”整理成可按目标进入、按阶段学习、按项目验证的知识路径，降低第一次阅读的认知负担，同时保留现有专题内容和链接稳定性。

## 目标

- 提供一个明确的 Java 后端总入口，说明读者先学什么、为什么学、学完产出什么。
- 按学习阶段重排侧边栏：基础底座、业务开发、框架与持久层、中间件与分布式、生产治理与面试。
- 把可运行示例工程作为主线验证场景，而不是孤立链接。
- 为专题文章统一展示“适合谁、前置知识、完成后会得到什么、如何验证、下一步读什么”。
- 保持现有文章路径可用，减少一次性迁移和链接风险。

## 非目标

- 本次不重写 29 篇专题的技术正文。
- 本次不新增外部依赖、不更换 VitePress 主题、不改 Java 示例工程业务逻辑。
- 不把 MySQL、DevOps 和系统设计全文复制到 Java 模块；只建立清晰的跨模块跳转。

## 方案比较

1. 只调整侧边栏：改动少，但正文缺少统一入口和学习闭环。
2. 新增总览与路线层，并重排导航：能快速建立信息架构，保留现有内容，作为本次方案。
3. 全量按课程重写：最终最整齐，但成本高、风险大，适合后续逐篇迭代。

## 设计

新增 `doc/Java/后端学习地图.md` 作为总览页，包含：

- 按目标进入：从零上手、已有 CRUD、准备面试、线上排障、接入中间件。
- 按阶段推进：语言与运行时 → 业务接口 → 持久层 → Spring → 中间件 → 分布式与治理。
- 每阶段的输入、必读文章、实践产出和完成标准。
- 示例工程的对应章节和验证命令。
- 专题选择表、跨模块边界、阅读约定和文章模板。

调整 `doc/Java/前言.md` 为简洁入口，把详细路线收敛到学习地图；在侧边栏中将学习地图置于最前，并按阶段分组现有文章。对高密度专题补充统一的“阅读卡片”区块，至少覆盖前置、产出、验证和下一步。

## 验收标准

- Java 侧边栏从入口开始能沿一条主线走完，不需要猜文章顺序。
- 新读者能在总览页确定自己的入口、阶段目标和下一篇文章。
- 示例项目能从总览页进入，并能看到启动、测试和验证位置。
- `npm run docs:build`（或仓库实际对应的构建命令）通过，新增链接无死链。
