# 技术资料验证与学习方法

## 解决什么问题

论坛、教程和产品宣传用于发现思路，技术事实需要可追溯的文档、版本和复现。资料数量多不等于知识完整，也不能因为标题写“工业级”“全景”就直接作为面试答案。

## 基本使用：验证一个知识点

1. 写下问题和实际用途，例如“如何还原 release 包崩溃行号”。
2. 查当前官方文档和工具版本，记录适用平台、前置条件、参数和限制。
3. 建最小示例，验证正常与至少一个失败场景。
4. 检查实现或可靠技术文章，解释已观察到的行为。
5. 记录结论、证据、未确定点和版本变化，形成自己的面试回答。

资料优先级通常是官方规范/版本文档 → 对应版本源码/测试 → 有实验和数据的工程文章 → 社区讨论。源码能说明实现，不能自动证明产品性能、服务价格或合规能力。

## 常见场景与核验标准

| 表述 | 需要的证据 |
|---|---|
| “比另一方案快” | 相同负载、硬件、版本、数据量和指标 |
| “完全免费/开源” | 当前价格、额度、依赖服务费用和许可证 |
| “不会丢数据/零停机” | 故障模型、持久化边界、恢复与切换实验 |
| “全版本支持” | 实际支持矩阵、系统限制和回归结果 |
| “只能这样实现” | 业务约束与替代方案的代价 |

## 面试学习方式

为每个主题准备六句话：解决的问题、基本用法、使用边界、失败案例、原理解释、验证证据。没有参与过的项目不要写成亲历；实验数据不能冒充生产指标。版本敏感结论在面试前复核。
