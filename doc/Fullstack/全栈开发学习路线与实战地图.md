# 全栈开发学习路线与实战地图

全栈开发不等于同时记住所有框架 API。有效的学习方式是围绕一个完整业务项目，依次完成页面、接口、数据库、部署和维护，再针对遇到的问题学习原理。

本文使用“任务管理系统”作为练习项目。项目包含用户注册登录、任务增删改查、分页筛选、文件上传、操作日志和管理员后台，规模适合个人学习，也足以覆盖常见企业开发流程。

## 一、先建立完整链路

一条业务请求通常经过以下步骤：

```text
浏览器 / 小程序
    ↓ HTTP 请求
Vue 页面与状态管理
    ↓ JSON
Spring Boot Controller
    ↓ 参数校验、鉴权、事务
Service 业务层
    ↓ SQL / 缓存 / 消息
MyBatis + MySQL + Redis + MQ
    ↓
日志、监控、部署与回滚
```

学习每项技术时，都回答四个问题：

1. 它解决什么业务问题？
2. 它在请求链路的哪一层？
3. 最小可运行代码是什么？
4. 出现故障时如何验证和回滚？

## 二、分阶段学习路线

### 阶段 1：Web 基础与页面实现

目标是能够独立完成一个可交互页面。

| 知识点 | 最小练习 | 验收标准 |
| --- | --- | --- |
| HTML 语义化 | 登录页、任务列表页 | 能正确组织表单、标题、列表和按钮 |
| CSS 布局 | 两栏后台、移动端卡片 | 能使用 Flex、Grid、媒体查询完成响应式布局 |
| JavaScript / TypeScript | 表单校验、数组筛选、异步请求 | 能读懂 Promise、async/await 和类型定义 |
| Vue 3 | 列表、详情、编辑表单 | 能使用组件、`ref`、`computed`、生命周期 |
| Vue Router / Pinia | 登录守卫、用户状态 | 刷新页面后状态恢复，未登录用户不能进入受保护页面 |
| Vite | 开发、构建和环境变量 | 能区分开发、测试和生产 API 地址 |

推荐阅读顺序：[CSS 布局与响应式实战](/doc/Vue/CSS布局与响应式实战) → [Vue 组合式 API](/doc/Vue/组合式API与实战解析) → [路由权限守卫](/doc/Vue/路由权限守卫与实战) → [Pinia 状态管理](/doc/Vue/Pinia状态管理与实战解析) → [工程化构建与部署](/doc/Vue/工程化构建与部署实战)。

### 阶段 2：Java 与 Spring Boot 接口

目标是能够完成一组可维护的增删改查接口。

| 知识点 | 最小练习 | 验收标准 |
| --- | --- | --- |
| Java 基础 | DTO、枚举、集合、异常 | 能区分实体、请求对象和响应对象 |
| Spring Boot | 创建应用、读取配置、启动接口 | 能使用 `application.yml` 管理环境配置 |
| Controller | `GET`、`POST`、`PUT`、`DELETE` | 返回结构统一，参数错误可读 |
| Service | 业务规则和事务边界 | Controller 不直接编写 SQL |
| MyBatis | Mapper、XML、分页查询 | SQL 可审查，参数使用预编译 |
| 参数校验 | `@Valid`、自定义校验 | 非法输入在进入业务层前被拒绝 |
| 异常处理 | `@RestControllerAdvice` | 客户端不接收堆栈信息，服务端保留完整日志 |

推荐阅读：[Spring Boot 业务开发实战入门](/doc/Java/SpringBoot业务开发实战入门) → [SQL 与 MyBatis 映射](/doc/Java/MyBatis/SQL与MyBatis映射实战全景对照) → [Spring 事务](/doc/Java/Spring/Spring核心与事务失效实战)。

### 阶段 3：SQL 与数据建模

目标是能够安全地设计表、编写查询和维护线上数据。

| 知识点 | 最小练习 | 验收标准 |
| --- | --- | --- |
| 表设计 | 用户、任务、标签、日志四张表 | 主键、唯一约束、外键关系和时间字段合理 |
| 基础 SQL | 增删改查、排序、分页 | 所有修改语句都有明确条件 |
| 多表查询 | 用户与任务、任务与标签 | 能判断 `INNER JOIN` 和 `LEFT JOIN` 的差异 |
| 事务 | 创建任务并写操作日志 | 事务边界明确，失败时数据不会只写一半 |
| 索引 | 用户名、状态、创建时间组合索引 | 能使用 `EXPLAIN` 验证索引是否有效 |
| 数据维护 | 备份、迁移、归档、修复 | 任何生产修改都有备份和回滚方案 |

推荐阅读：[SQL 编写与生产维护实战](/doc/MySQL/SQL编写与生产维护实战) → [索引失效与优化](/doc/MySQL/MySQL索引失效与优化实战) → [事务隔离与 MVCC](/doc/MySQL/MySQL事务隔离与MVCC原理)。

### 阶段 4：缓存、消息和异步任务

目标是理解什么时候需要引入中间件，以及引入后如何保证一致性。

- Redis：缓存热点查询、保存短期验证码、实现限流计数。
- 消息队列：把通知、日志、耗时任务从主请求中拆出。
- 定时任务：处理超时任务、清理临时文件和生成报表。
- 分布式锁：只有在数据库约束、唯一键和原子更新不足时使用。

学习顺序应先完成数据库版本，再为明确的性能或解耦问题增加中间件。每增加一个中间件，都记录数据来源、失败重试、幂等键和补偿方式。

### 阶段 5：部署、监控与维护

目标是让应用能够被部署、观测和恢复。

1. 使用 Docker 固化运行环境。
2. 使用环境变量或密钥服务管理数据库密码、JWT 密钥和第三方凭证。
3. 使用健康检查确认应用、数据库和 Redis 可用。
4. 使用结构化日志记录请求 ID、用户 ID、耗时和错误码。
5. 发布前执行数据库迁移、接口回归和前端产物检查。
6. 发布后观察错误率、P95 延迟、数据库连接数和慢 SQL。
7. 出现异常时优先回滚应用版本，涉及数据时按照预先准备的补偿脚本处理。

## 三、按周执行的学习计划

| 周次 | 交付结果 | 重点能力 |
| --- | --- | --- |
| 第 1 周 | 静态登录页和任务列表 | HTML、CSS、JavaScript、Git |
| 第 2 周 | Vue 页面和路由权限 | Vue 组件、Router、Pinia、TypeScript |
| 第 3 周 | Spring Boot 用户与任务接口 | Controller、Service、DTO、异常处理 |
| 第 4 周 | MySQL 表结构和完整 CRUD | SQL、MyBatis、事务、索引 |
| 第 5 周 | 登录鉴权和文件上传 | JWT、权限模型、对象存储或本地文件服务 |
| 第 6 周 | Redis 缓存和异步通知 | 缓存失效、幂等、消息重试 |
| 第 7 周 | Docker 部署和日志监控 | 镜像、环境变量、健康检查、回滚 |
| 第 8 周 | 故障演练和文档整理 | 慢 SQL、接口超时、数据恢复、复盘 |

每周必须保留三个产物：可运行代码、接口或数据变更说明、一次故障排查记录。只阅读文章而没有可运行结果，无法形成实战能力。

## 四、学习中的判断标准

### 先完成业务，再深入原理

第一次实现登录时，先完成请求、响应、错误提示和退出登录。完成后再学习 Token、过滤器、拦截器和密码哈希的底层机制。这样每个原理都有实际代码可以对应。

### 优先掌握边界和失败场景

每个功能至少测试以下情况：

- 参数为空、格式错误或超出长度。
- 用户没有权限，或 Token 已过期。
- 数据不存在、重复提交或重复创建。
- 数据库连接失败、缓存不可用、消息发送失败。
- 网络超时、客户端重复请求和服务重启。

### 每篇笔记采用固定结构

建议每篇文章都包含：

1. 业务问题与使用场景。
2. 最小可运行代码。
3. 请求链路或数据流图。
4. 配置项和启动命令。
5. 常见错误与排查方法。
6. 生产环境的边界、风险和回滚方案。

这套结构可以让知识从“看过”变成“能够实现、能够解释、能够维护”。
