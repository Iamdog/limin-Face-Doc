# 全栈开发与工程化栏目地图

## 先会使用，再逐步深入

从[本模块的基础实践](/doc/Fullstack/全栈开发学习路线与实战地图)开始，先说明技术解决的业务问题，完成基本 API、最小流程和失败验证；再阅读本页后续专题。

学习与面试都按 **用途 → 基本使用 → 常见场景与边界 → 排错与优化 → 原理与源码 → 方案取舍** 推进。每个知识点至少能给出一个正常操作、一个失败案例和验证证据。

全库覆盖情况与跨模块路线见[知识库检查与分层学习地图](/doc/知识库检查与分层学习地图)。

全栈开发的核心是完成一条可验证、可部署、可维护的业务链路：页面发起请求，后端处理规则，数据库保存事实，部署系统提供运行环境，日志和监控负责定位问题。

## 推荐阅读顺序

前端布局与 Vue → 接口和 Java → SQL 与 MyBatis → 登录与权限 → 缓存和消息 → Docker 与 CI/CD → 监控、故障排查和系统设计。

每完成一个模块，都应留下接口示例、数据库变更脚本、运行命令和故障记录。这样可以从“会写功能”逐步过渡到“能维护系统”。
