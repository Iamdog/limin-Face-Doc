# Java 后端与全栈架构前言

## 已会 CRUD，优先补事务、权限与排错

如果已经能独立写简单接口，先走 [CRUD 之后的后端补强路线](/doc/Java/CRUD之后的后端补强路线)，用 [事务、权限与排错实战](/doc/Java/事务权限与排错实战) 和 [可运行项目](/examples/java-backend-workshop/README) 验证多表回滚、数据归属、角色权限、版本冲突与请求日志。

这条路线先验证业务结果，再解释代理、隔离级别和安全链。完成后再按项目需要进入 Redis、MQ、并发、JVM 和微服务专题。

## 先会使用，再逐步深入

从[本模块的基础实践](/doc/Java/Java语言基础与日常开发)开始，先说明技术解决的业务问题，完成基本 API、最小流程和失败验证；再阅读本页后续专题。

学习与面试都按 **用途 → 基本使用 → 常见场景与边界 → 排错与优化 → 原理与源码 → 方案取舍** 推进。每个知识点至少能给出一个正常操作、一个失败案例和验证证据。

全库覆盖情况与跨模块路线见[知识库检查与分层学习地图](/doc/知识库检查与分层学习地图)。

> **这个板块关心的是「一条请求的完整旅程」**：从接收 HTTP、校验输入和身份，到业务事务与参数化 SQL，再到失败定位和恢复；需要时才扩展缓存、消息和跨服务调用。每一层都可能成为瓶颈，所以每一层都要知道「机制是什么、参数怎么配、坑在哪」。

## Java 后端实战主线

没有完整项目经验时，建议先完成一条最小业务链路，再学习分布式组件。推荐顺序如下：

1. [Spring Boot 业务开发实战入门](/doc/Java/SpringBoot业务开发实战入门)：完成 Controller、Service、Mapper、参数校验、异常处理和事务。
2. [SQL 编写与生产维护实战](/doc/MySQL/SQL编写与生产维护实战)：掌握表设计、增删改查、连接、分页、索引、事务和数据修复。
3. [SQL 与 MyBatis 映射实战](/doc/Java/MyBatis/SQL与MyBatis映射实战全景对照)：理解 Java 方法、Mapper XML 和 SQL 参数之间的对应关系。
4. [Redis 高并发缓存与一致性](/doc/Java/Redis高并发缓存与一致性实战)：在出现明确的热点读和性能问题后引入缓存。
5. [Kafka 与 RocketMQ 生产级接入](/doc/Java/Kafka与RocketMQ生产级接入实战)：理解消息确认、重试、幂等和补偿。
6. [SpringCloud 微服务核心组件](/doc/Java/Spring/SpringCloud微服务核心组件与架构实战)：在单体应用边界清晰后，再拆分服务和配置中心。

每完成一个阶段，都应保留可运行代码、接口说明、数据库变更脚本和一次故障排查记录。这样可以同时积累框架使用经验和生产维护能力。

## Java 后端 MVP 场景

| 场景 | 推荐实现 | 进入下一阶段的条件 |
|---|---|---|
| 用户、任务、订单 CRUD | Spring Boot 单体 + MyBatis + MySQL | 先完成参数校验、权限、事务和审计日志 |
| 登录与权限 | Spring Security 或项目统一鉴权层 + Token/Session | 明确匿名接口、用户接口和管理员接口边界 |
| 热点查询 | MySQL 索引 + Cache Aside Redis | 通过慢查询和访问量证明缓存必要性 |
| 通知和耗时任务 | 消息队列 + 消费幂等 + 重试 | 明确消息 ID、失败补偿和死信处理 |
| 服务拆分 | 模块化单体 → 独立服务 | 具备独立扩容、发布隔离或团队边界 |

MVP 阶段的首要目标是让一条请求能够被实现、测试、定位和恢复。框架数量不代表后端能力，稳定的边界、数据约束和故障处理才是进入生产环境的基础。
