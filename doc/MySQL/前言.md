# MySQL 数据库与 SQL 实战地图

## 先会使用，再逐步深入

从[本模块的基础实践](/doc/MySQL/SQL编写与生产维护实战)开始，先说明技术解决的业务问题，完成基本 API、最小流程和失败验证；再阅读本页后续专题。

学习与面试都按 **用途 → 基本使用 → 常见场景与边界 → 排错与优化 → 原理与源码 → 方案取舍** 推进。每个知识点至少能给出一个正常操作、一个失败案例和验证证据。

全库覆盖情况与跨模块路线见[知识库检查与分层学习地图](/doc/知识库检查与分层学习地图)。

MySQL 学习应同时覆盖“如何查询”和“如何安全维护”。本栏目先用单库完成业务，再逐步学习索引、事务、复制、读写分离和大表治理。

## MVP 使用场景

| 场景 | MVP 实现 | 升级边界 |
|---|---|---|
| 用户、任务、订单 | InnoDB + 主键 + 唯一约束 + 事务 | 数据量、写入量或可用性达到容量边界时扩展 |
| 管理后台查询 | 明确字段 + 分页 + 组合索引 | 慢查询持续出现时使用 `EXPLAIN`、归档或读副本 |
| 状态流转 | 状态字段 + 条件更新 + 操作日志 | 并发冲突增加时引入乐观锁或状态机 |
| 历史日志 | 按时间或主键分批归档 | 数据量持续增长时使用分区、冷热分层或独立日志库 |
| 备份与恢复 | 定期备份 + 恢复演练 | 需要更短恢复时间时增加 binlog 和高可用架构 |

## 生产维护原则

- 任何生产修改都必须先确认环境、预览数据、记录影响行数，并准备回滚方案。
- 业务约束优先落在数据库唯一键、检查条件和事务中，不能只依赖应用代码。
- 索引需要根据查询和写入代价设计，不能因为“可能用到”就无限增加。
- 备份必须通过恢复演练验证，备份文件存在不等于能够恢复业务。
