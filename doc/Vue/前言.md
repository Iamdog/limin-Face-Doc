# Vue 前言与阅读地图

## 先会使用，再逐步深入

从[本模块的基础实践](/doc/Vue/JavaScript与浏览器基础实战)开始，先说明技术解决的业务问题，完成基本 API、最小流程和失败验证；再阅读本页后续专题。

学习与面试都按 **用途 → 基本使用 → 常见场景与边界 → 排错与优化 → 原理与源码 → 方案取舍** 推进。每个知识点至少能给出一个正常操作、一个失败案例和验证证据。

全库覆盖情况与跨模块路线见[知识库检查与分层学习地图](/doc/知识库检查与分层学习地图)。

> **一句话看懂本栏目**：按「**原理 → 组件 → 路由/状态 → 渲染 → 工程化**」五层组织。**这里只给地图与路线，具体有哪些篇以左侧目录为准**——清单会持续变，地图不会。

## 覆盖哪些能力域

| 层次 | 回答的核心问题 | 入口示例 |
|---|---|---|
| **① 响应式与运行时内核** | 数据变了怎么通知到视图？Proxy 与 `defineProperty` 到底差在哪？为什么解构会丢响应？ | [响应式原理](/doc/Vue/响应式原理与实战解析) |
| **② 组件模型** | 父子钩子什么顺序？props / emit / provide / expose 怎么选？`v-model` 展开成什么？ | [组件通信](/doc/Vue/组件通信与实战解析) |
| **③ 路由与状态** | 动态路由怎么加？守卫谁先谁后？前端权限模型怎么分层？Pinia 为什么去掉 mutation？ | [路由权限守卫](/doc/Vue/路由权限守卫与实战) |
| **④ 渲染与更新调度** | vnode 怎么生成？双端 diff 与最长递增子序列怎么减少 DOM 操作？为什么改完数据立刻读 DOM 是旧值？ | [渲染机制与 Diff](/doc/Vue/渲染机制与Diff算法深度解析) |
| **⑤ 工程化与构建** | Vite 和 Webpack 差在哪？产物怎么拆？发布后白屏怎么回滚？ | [工程化构建与部署](/doc/Vue/工程化构建与部署实战) |
| **⑥ 性能与可维护性** | 指标怎么定？瓶颈在编译期、响应式还是渲染层？每个优化手段的代价是什么？ | [性能优化与实战总结](/doc/Vue/性能优化与实战总结) |

> 这五层不是「章节顺序」，而是**排查顺序**：页面卡 → 先看渲染层有没有多余更新 → 再看响应式依赖是不是建多了 → 最后看构建产物是不是没拆包。任何单点问题放回链路里都能定位。

## MVP 实现与使用场景

| 场景 | MVP 推荐实现 | 何时升级 |
|---|---|---|
| 中后台系统 | Vue 3 + `script setup` + TypeScript + Vite + Router + Pinia | 页面权限、表格筛选和表单复杂度增加时拆分业务模块 |
| 内容和营销页面 | Vue 组件 + CSS 响应式 + API 请求封装 | 首屏和 SEO 成为核心指标时评估 SSR 或静态生成 |
| 小程序和 H5 | Uni-App 或 Vue 3 Web 项目，统一接口模型 | 平台能力、包体积或设备能力成为瓶颈时分层处理 |
| 组件库建设 | 先建立业务组件和设计变量，再抽取通用组件 | 三个以上页面出现相同交互并且规则稳定时再抽象 |

新项目默认使用 Composition API、单文件组件和 TypeScript。MVP 阶段优先完成“路由 → 接口 → 表单 → 状态 → 错误和空数据状态”这条链路，不应先建设复杂的组件平台。

## 三条阅读路线

| 路线 | 目标 | 顺序 |
|---|---|---|
| **面试主线** | 能从实际使用逐层解释行为 | JS/浏览器 → Vue 页面 → 组件/表单/路由/状态 → 失败场景 → 响应式/调度/Diff → 性能取舍 |
| **业务开发主线** | 能独立搭中后台 | 组件通信 → v-model → VueRouter → 权限守卫 → Pinia → TypeScript → 工程化 |
| **查漏速查** | 手上有具体 bug | 直接跳到对应能力域，看那篇的「30 秒速览」与「生产避坑清单」 |

## 一条串讲主线（背下来能撑住整场 Vue 面试）

```mermaid
flowchart LR
    A["数据层<br/>Proxy 建依赖"] --> B["调度层<br/>trigger 入队合批"]
    B --> C["渲染层<br/>vnode + patchFlag + diff"]
    C --> D["组件层<br/>props 下行 / emit 上行"]
    D --> E["应用层<br/>路由守卫 + Pinia"]
    E --> F["优化层<br/>按指标逐层减依赖/减 vnode/减 DOM"]
```

> **数据层**：`ref` / `reactive` 用 Proxy 建依赖 → **调度层**：修改时 `trigger` 把 effect 压入微任务队列合批，`nextTick` 后 DOM 才更新 → **渲染层**：render 生成带 `patchFlag` 的 vnode，diff 用 key + 最长递增子序列最小化 DOM 操作 → **组件层**：props 下行、emit 上行，`v-model` 是这两者的语法糖 → **应用层**：路由守卫决定能不能进、Pinia 管跨页状态、Vite 决定产物怎么拆怎么发 → **优化层**：从指标定位瓶颈，逐层减少依赖、vnode、DOM 和长任务。

## 边界：这个栏目不是什么

- **不是 Vue 全量手册**。API 细节以官方文档为准，这里只写「官方文档不会告诉你的取舍与坑」。
- **不深入**：Nuxt / SSR 渲染细节（仅 Pinia、工程化篇各提一段）、微前端方案、可视化与低代码、Electron / Tauri 桌面端。
- CSS 页面布局与响应式适配请阅读 [CSS 布局与响应式实战](/doc/Vue/CSS布局与响应式实战)；浏览器渲染和网络协议仍分别参见 [性能优化](/doc/Vue/性能优化与实战总结) 与 [计算机网络全解](/doc/Network/计算机网络与核心通信协议全解)。
- 移动端与小程序方向请走 [Uni-App 板块](/doc/uniapp/前言) 或 [Flutter 板块](/doc/flutter/前言)，两者的组件与生命周期模型和 Vue 不同。
