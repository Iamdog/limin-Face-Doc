# 模型调用、RAG 与评测基础

## 解决什么问题

模型调用适合问答、摘要和结构化提取；RAG 为回答提供外部知识；工作流控制多步过程；工具调用让模型请求外部能力。先验证一个稳定任务，再决定是否需要框架和 Agent。

## 基本使用：从一次可靠调用开始

最小服务链路为输入校验 → 构造提示 → 调用模型 → 校验输出 → 返回结果。API 密钥在服务端管理，配置超时、取消、有限重试和并发上限。客户端只能访问自己的应用接口。

以下是与供应商无关的伪代码，具体 SDK 语法按所选服务版本实现：

```text
input = validate_user_input(request)
prompt = build_prompt(template_version, input)
response = model.generate(prompt, deadline, output_schema)
if response.refused_or_incomplete:
    return explicit_failure
result = validate_schema_and_business_rules(response.output)
record_metrics(model_version, prompt_version, latency, usage, outcome)
return result
```

验证正常输入、超长输入、超时、限流、拒答、格式错误和取消。结构化输出提高格式可靠性，但不能保证事实正确，金额、日期、权限和业务约束仍由程序验证。

## 必备概念按使用理解

| 概念 | 用于什么 | 边界 |
|---|---|---|
| Token 与上下文 | 控制输入输出长度和成本 | 上下文有上限，输入/输出成本和计量依模型而异 |
| Prompt | 指定任务、格式、证据和示例 | 指令不能取代权限控制与事实验证 |
| temperature | 在支持该参数时调节采样 | 低温不能保证无幻觉；参数支持按模型确认 |
| Embedding | 语义检索与相似度计算 | 模型、维度、距离度量和索引要匹配 |
| RAG | 将检索证据提供给生成 | 检索错、权限错、证据过期会直接影响回答 |
| 工具调用 | 让模型提议调用外部能力 | 实际执行由程序检查参数、权限和副作用 |
| 工作流 / Agent | 固定步骤或动态选择动作 | 循环次数、deadline、成本和停止条件需限制 |
| MCP | 标准化连接工具和资源 | 协议本身不能自动保证工具可信和用户授权 |

## 基本 RAG 流程

文档解析 → 按结构切分 → 保存来源/版本/权限 → embedding → 建索引 → 检索 → 必要时重排 → 拼证据 → 回答并引用。先用少量已知文档和十几个问题跑通，不必同时引入所有框架。

检索前按用户/租户过滤，返回结果再校验权限；“生成时让模型不要泄露”不能补救越权检索。资料更新或删除时同步索引，保留文档版本和引用定位。没有足够证据时明确表示无法确认。

## 常见场景：评测与故障定界

| 故障 | 先观察 | 改进方向 |
|---|---|---|
| 没检索到正确资料 | 固定问题的召回结果 | 解析、切分、查询改写、混合检索 |
| 检索有证据但答错 | prompt、上下文、回答引用 | 重排、证据组织、任务限制和输出校验 |
| 成本高、延迟长 | token、步骤数、p95、并发 | 缩短上下文、缓存、减少循环、模型选择 |
| 用户请求串线 | 会话 ID、租户和状态存储 | 隔离上下文、验证缓存键和工作流状态 |
| 提示注入 | 外部文档与工具返回内容 | 视作不可信数据；执行层做独立权限校验 |

评测集包含可回答、无证据、冲突资料、过期资料、越权和恶意指令。分别衡量召回质量、答案正确/忠实程度、引用有效性、错误率、延迟和成本。人工标注和规则评测为基础，模型评分仅作辅助。记录模型、prompt、数据集和索引版本，才可复现改进结果。

## 面试递进

| 基础题 | 场景追问 | 深入方向 |
|---|---|---|
| 如何调用模型处理超时？ | 重试会不会重复操作？ | deadline、预算、幂等与取消 |
| 什么时候用 RAG？ | 知识变化如何同步？ | 解析、版本、检索评测和索引更新 |
| embedding 有什么用？ | 关键词精准但语义检索遗漏？ | 混合检索、重排、召回与精度 |
| Agent 比工作流多什么？ | 反复循环或工具失败怎么办？ | 状态机、停止条件、人工接管 |
| 怎么判断效果变好？ | 模型升级后如何回归？ | 固定评测集、分层指标和灰度 |
