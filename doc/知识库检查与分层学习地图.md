# 知识库检查与分层学习地图

## 结论：专题丰富，原基础层和学习顺序不够系统

本次以 2026-11-12 工作区中的 **154 篇文档、14 个原有模块** 为基线。Android、Java/MySQL、Vue 的专题覆盖较广，但“文章多”不能证明基础完整。原结构的主要问题是：有些文章开头直接进入源码/底层追问；基本操作与失败验证不足；跨模块前置知识分散；部分方案带有绝对化保证。

本次全量检查文章清单、章节与入口，针对关键技术边界深入校正，并补充 17 篇基础/专项实践。逐篇结构事实见 [专题检查清单](/doc/专题逐篇检查清单)。这不是对所有历史代码片段的逐行运行认证；需要设备、数据库、Broker 或平台 SDK 的示例仍需在对应环境验证。

## 一、所有知识点先按六层检查

| 层级 | 必须能回答 | 必须能做或拿出什么 |
|---|---|---|
| 1. 解决问题 | 为什么需要它？不用会怎样？ | 一个明确业务场景和适用边界 |
| 2. 基本使用 | 怎么接入？输入输出是什么？ | 前置环境、基本 API、最小流程与预期结果 |
| 3. 常见场景 | 开发中怎么组合？哪里易错？ | 空值、失败、取消、重试、重复操作等验证 |
| 4. 排错优化 | 如何发现、定位、修复？ | 日志/指标/复现/对照结果组成的证据链 |
| 5. 原理源码 | 为什么会有这些行为？ | 对应实现和版本；解释已观察的现象 |
| 6. 取舍深入 | 为什么选它？何时换方案？ | 性能、一致性、复杂度、恢复和维护成本 |

原理和源码应帮助解释使用中的问题。连基本 API 和失败路径都没验证时，不从“底层三件套”开始背。

回答一个主题至少准备：用途、基本操作、边界、失败案例、原理、验证证据。初级优先前 3 层；中级应能完成定位与修复；高级再深入实现、容量、一致性和恢复取舍。层级取决于岗位，不能把背源码当作经验替代。
