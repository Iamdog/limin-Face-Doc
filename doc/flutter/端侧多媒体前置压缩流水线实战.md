# 端侧多媒体前置压缩流水线实战 (flutter_image_compress + video_compress)

## 使用入口：先解决问题，再做验证

控制上传体积与处理峰值。

**先做基本操作**：先用沙盒副本压缩单文件并测体积/耗时，限制并发，验证失败、取消和清理。初次学习可先完成[本模块基础实践](/doc/flutter/Dart与Flutter页面基本使用)。

**再逐步深入**：基本 API 与输入输出 → 常见失败和使用边界 → 场景排查与优化 → 本文机制分析与源码。面试先讲用途和自己的操作过程，再回答场景与原理追问。

在相册类应用中，用户随手拍摄的照片动辄 4~12MB，3 分钟手机录制视频可达 200MB~500MB+。若不做端侧前置压缩直接上传：
1. **网络超时率剧增**：弱网环境下极易触发 HTTP 超时与重试雪崩；
2. **带宽与存储成本高昂**：服务器 COS/OSS 存储与流量费用几何级膨胀；
3. **用户体验极差**：上传菊花长时间转动，甚至因内存 OOM 导致 App 被系统杀掉。

## 二、 核心架构原则：沙盒副本机制

```mermaid
flowchart LR
    A[系统相册原始资产\n(不可变 / 零修改)] -->|读取字节流| B[端侧压缩引擎]
    B -->|降采样 & 码率控制| C[应用临时目录 tempDir\n(仅供上传用的轻量副本)]
    C -->|Dio 并发切片上传| D[云端对象存储]
    D -.->|上传完毕 / 失败| E[立即清理临时文件]
```

> [!IMPORTANT]
> **绝对准则**：严禁直接覆盖或修改用户手机本地原始相册中的照片和视频文件！压缩只应在 App 的 `getTemporaryDirectory()` 沙盒目录中生成临时副本，上传完成后及时删除清理。

## 三、 企业级压缩流水线封装

```dart
// lib/core/compression/media_compress_service.dart
import 'dart:io';
import 'package:flutter_image_compress/flutter_image_compress.dart';
import 'package:path_provider/path_provider.dart';
import 'package:video_compress/video_compress.dart';

class MediaCompressService {
  /// 图片高质量降采样压缩
  /// [rawFile]: 本地原图文件
  /// [quality]: 压缩质量比（80~85 为视觉无损甜点区间）
  static Future<File?> compressImage(
    File rawFile, {
    int quality = 85,
    int minWidth = 1920,
    int minHeight = 1080,
  }) async {
    try {
      final tempDir = await getTemporaryDirectory();
      final targetPath =
          '${tempDir.path}/img_cmp_${DateTime.now().millisecondsSinceEpoch}.jpg';

      final XFile? compressedXFile = await FlutterImageCompress.compressAndGetFile(
        rawFile.absolute.path,
        targetPath,
        quality: quality,
        minWidth: minWidth,
        minHeight: minHeight,
        autoCorrectionAngle: true, // 关键：自动校正 EXIF 拍摄角度，防止横图倒立
        format: CompressFormat.jpeg,
      );

      if (compressedXFile == null) return null;
      return File(compressedXFile.path);
    } catch (e) {
      print('图片压缩失败，回退使用原图: $e');
      return rawFile; // 降级兜底方案
    }
  }

  /// 视频转码与码率压缩
  /// [rawVideo]: 原始本地视频文件
  /// [onProgress]: 压缩百分比回调 (0~100)
  static Future<File?> compressVideo(
    File rawVideo, {
    VideoQuality quality = VideoQuality.MediumQuality, // 压缩至 720P 左右
    Function(double progress)? onProgress,
  }) async {
    Subscription? subscription;
    try {
      if (onProgress != null) {
        subscription = VideoCompress.compressProgress$.subscribe((progress) {
          onProgress(progress);
        });
      }

      final MediaInfo? info = await VideoCompress.compressVideo(
        rawVideo.path,
        quality: quality,
        deleteOrigin: false, // 严禁删除原始视频！
        includeAudio: true,
        frameRate: 30, // 稳定帧率至 30fps
      );

      return info?.file;
    } catch (e) {
      print('视频压缩异常: $e');
      return rawVideo;
    } finally {
      subscription?.unsubscribe();
      // 释放底层原生转码资源，防止内存泄漏
      VideoCompress.dispose();
    }
  }

  /// 取消当前正在进行的视频压缩（如用户返回或放弃上传）
  static Future<void> cancelVideoCompression() async {
    await VideoCompress.cancelCompression();
  }
}
```

## 四、 常见高频生产避坑

1. **iOS HEIC 格式图片崩溃**：苹果新机型默认拍摄格式为 HEIC/HEIF。直接按常规文件读取可能发生解码失败。`flutter_image_compress` 内部能够原生解码 HEIC 并转换输出为标准 JPG，必须配置 `format: CompressFormat.jpeg`。
2. **EXIF 旋转元数据丢失**：许多原图在手机内虽然是正向的，但实际上是带有了 `Orientation = 6 / 8` 的旋转元信息。如果在压缩时不开启 `autoCorrectionAngle: true`，压缩后生成的图片会导致上传后在网页端或安卓端呈现“头朝下”倒立倒转现象。
