# 浙政钉（政务协同平台）开发前言

## 先会使用，再逐步深入

从[本模块的基础实践](/doc/浙政钉/身份接入权限与联调实践)开始，先说明技术解决的业务问题，完成基本 API、最小流程和失败验证；再阅读本页后续专题。

学习与面试都按 **用途 → 基本使用 → 常见场景与边界 → 排错与优化 → 原理与源码 → 方案取舍** 推进。每个知识点至少能给出一个正常操作、一个失败案例和验证证据。

全库覆盖情况与跨模块路线见[知识库检查与分层学习地图](/doc/知识库检查与分层学习地图)。

> **一句话看懂**：浙政钉不是「钉钉换个皮肤」，而是**专有部署的政务协同底座**——应用要走政务侧审核上架、要适配专有网络与账号体系、接口与标准钉钉开放平台并不完全通用。这个板块记录实际走过的流程与环境约束，篇目少，但都是踩出来的。

| 能力域 | 说明 | 入口 |
|---|---|---|
| **上架与发布** | 应用注册、材料准备、审核、发布与版本更新，各环节卡点 | [浙政钉开发上架流程](/doc/浙政钉/浙政钉开发上架流程) |
| **开发环境基线** | 工具链与脚手架版本约束，见下表 | 本文 |

**环境基线**（随项目推进更新，不同批次可能不同，以实际收到的为准）：

| 项 | 版本 / 说明 |
|---|---|
| 开发工具 | 支付宝小程序开发工具 `v3.8.4` |
| 脚手架 | uni-app `2.0.2-3071120230427001` |
| 运行形态 | 小程序形态运行在浙政钉容器内，非独立 App |

> 之所以用支付宝小程序开发工具：浙政钉的小程序容器与支付宝小程序技术栈同源，但**能力集是裁剪过的**，通用小程序 API 不能想当然直接用。

## MVP 实现与使用场景

| 场景 | MVP 实现 | 上线前重点验证 |
|---|---|---|
| 内部查询和填报 | Uni-App 页面 + 组织身份 + 后端接口 | 登录态、组织权限、数据脱敏和弱网重试 |
| 工单和审批 | 表单、状态流转、附件上传和消息提醒 | 审核路径、权限范围、重复提交和附件大小 |
| 政务数据看板 | 分页查询、统计接口和缓存 | 数据口径、更新时间、权限隔离和导出限制 |
| 已有 Web 能力迁移 | 复用业务层和接口层，重写容器适配层 | API 差异、组件限制、审核材料和专有网络 |

MVP 阶段应先验证“账号能登录、核心页面能打开、数据能提交、审核员能复现”。涉及组织通讯录、单点登录、消息推送和专有网络时，应在核心流程稳定后逐项接入。

## 边界：这个栏目不是什么

- **只讲浙政钉 / 专有钉钉这条线**，不覆盖标准钉钉开放平台（dingtalk.com）的 ISV 应用开发与上架，两者主体、审核流程、API 权限模型都不同。
- **不涉及政务资质与合规本身**（等保、密评、备案），只在流程篇里说明「需要准备哪些材料」。
- 身份、组织权限和专网排错方法见 [身份接入与联调实践](/doc/浙政钉/身份接入权限与联调实践)；具体 SDK/API 和消息/通讯录操作必须以部署方版本文档和真实联调补齐。
