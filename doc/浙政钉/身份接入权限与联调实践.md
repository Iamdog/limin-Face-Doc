# 浙政钉身份接入、权限与联调实践

## 解决什么问题

政务容器中的业务需要确认身份、组织范围、专有网络和平台能力。先完成登录、权限和一条接口，再进入上架审核；不能将标准钉钉的接口名、SDK 和权限直接套用到专有部署。

## 基本使用：最小接入链路

1. 向部署方取得当前环境的应用标识、容器 SDK、身份协议、网关地址、回调白名单和测试账号。
2. 建立开发、测试、生产配置，区分应用凭据与域名；服务端密钥只保存于受控服务端环境。
3. 客户端通过容器实际提供的能力获取临时身份凭证，服务端按该环境协议验证并映射业务账号。
4. 服务端签发业务会话，接口按用户、组织、租户和数据范围授权。
5. 用普通用户、跨组织用户和管理员账号验证查询与提交，再完成弱网、会话过期和退出。

本页提供接入与验收方法，不给未经实际部署文档确认的接口名。不同批次、容器和项目的能力可能不同，应保存实际版本和联调记录。

## 常见场景

| 场景 | 最小方案 | 验证重点 |
|---|---|---|
| 单点登录 | 容器身份→服务端验证→业务会话 | 凭证过期、防重放、账号停用 |
| 组织通讯录 | 按批准范围同步所需字段 | 最小权限、增量、删除/调岗、数据留存 |
| 工单审批 | 服务端状态机和资源权限 | 越级审批、重复提交、并发状态更新 |
| 消息通知 | 业务事件→平台消息→发送结果 | 对象范围、失败重试、频率和审计 |
| 附件上传 | 受控存储和授权下载 | 专网可达、大小、类型、脱敏与访问过期 |

## 专有网络联调顺序

容器是否支持该 API → 域名白名单 → DNS 和路由 → 网关/代理 → TLS 证书链 → 身份认证 → 组织权限 → 业务数据。逐段记录时间、错误码和 TraceId；工具能访问不代表容器在相同网络下能访问。测试账号和审核账号应能走完整核心流程。

## 面试与项目答辩

先讲业务解决什么问题、环境和身份怎么接、权限怎么验，再讲专网故障和审核材料，最后讨论容器与开放平台差异。能给出接入环境矩阵、身份时序、接口权限清单、失败测试与发布回退，比背不确定的 API 名称更有价值。
