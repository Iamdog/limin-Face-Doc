# 微信小程序快速部署与上架审核

> 本文按照小程序上线所需的实际顺序，说明账号申请、域名与服务部署、备案、审核材料准备和版本发布流程。内容适用于原生微信小程序，也适用于使用 Uni-App 编译到微信小程序的项目。

## 术语说明

| 术语 | 含义 |
| --- | --- |
| API | 小程序调用后端服务的接口地址，例如 `https://api.example.com`。 |
| 域名 | 用户访问服务时使用的地址，例如 `api.example.com`。 |
| HTTPS | 加密的网络通信协议，微信小程序的网络请求必须使用 HTTPS。 |
| Cloudflare Tunnel | 将本地或内网服务连接到公网的工具，适合 MVP 和联调场景。 |
| MVP | 最小可行版本，用于验证核心功能和上线流程。 |

## 一、准备事项

| 项目 | 需要准备的内容 |
| --- | --- |
| 主体资料 | 个人身份证、手机号、邮箱；企业营业执照、法人信息、对公或管理员信息 |
| 小程序账号 | 微信公众平台账号、小程序 AppID、管理员微信 |
| 后端服务 | 一个能稳定运行的 API 服务，以及可公网访问的域名 |
| 合规材料 | 小程序名称、服务类目、隐私协议、用户协议、客服联系方式 |
| 审核资料 | 首页和核心功能截图、测试账号、登录说明、特殊权限说明 |

整体流程如下：

```text
微信公众平台账号
        ↓
小程序 AppID + 开发成员
        ↓
ICP备案域名 + HTTPS
        ↓
合法域名配置 + 真机联调
        ↓
体验版测试 + 审核材料
        ↓
提交审核 → 审核通过 → 发布线上版本
```

## 二、申请微信小程序账号及应用

### 1. 注册小程序账号

访问[微信公众平台](https://mp.weixin.qq.com/)，选择“注册账号 → 小程序”，根据主体类型完成注册：

1. 选择个人或企业主体，填写邮箱、密码和管理员微信。
2. 完成邮箱激活、管理员身份验证和主体信息填写。
3. 设置小程序名称、头像、简介和服务类目。
4. 进入“开发 → 开发管理 → 开发设置”，记录 `AppID`。服务端需要调用微信接口时，根据页面指引生成或配置 `AppSecret`。
5. 在“成员管理”中添加开发者、体验者和运营人员，避免所有操作都依赖注册管理员。

个人主体在支付、企业认证、部分服务类目和主体能力方面存在限制。业务需要支付能力、企业主体能力或长期运营时，应使用企业主体申请。

### 2. 创建第一个可审核版本

在微信开发者工具中导入项目，填写 AppID，完成以下检查：

- `project.config.json` 中的 AppID 与公众平台一致。
- 生产环境接口地址已经从 `localhost`、内网 IP 或测试地址切换为正式域名。
- 关闭调试开关和测试按钮，移除固定验证码与写死的演示数据。
- 用真机验证登录、图片上传、文件下载、支付前置流程和异常提示。

使用 Uni-App 时，发行前应确认目标平台为“微信小程序”，并检查条件编译、分包和 `manifest.json` 中的 AppID 配置。

## 三、小程序备案流程

小程序备案和域名备案属于两项不同的备案。小程序备案针对小程序主体和服务，域名备案针对网站或接口使用的域名。接入境内服务器、使用正式域名或进行长期运营时，应同时规划两项备案，避免在审核阶段补充材料。

### 1. 费用说明

按本文整理时的项目预算口径，个人备案可预留约 **30 元**，企业备案可预留约 **300 元**。该金额多为服务商或代办渠道的服务费用，不代表微信官方固定收费。不同主体、地区和办理渠道的费用可能不同，实际金额以提交时的平台和服务商页面为准。

### 2. 备案材料

- 个人：身份证正反面、本人手机号、管理员微信和人脸核验信息。
- 企业：营业执照、法人信息、管理员信息、授权委托书（如管理员不是法人）。
- 域名：域名持有者信息要和备案主体匹配，准备域名证书或注册信息截图。
- 服务信息：小程序名称、简介、服务类目、服务器或云服务商信息。
- 联系方式：备案联系人必须能接听核验电话或短信。

### 3. 实际办理步骤

1. 登录微信公众平台，在“设置与开发”中找到小程序备案入口。
2. 填写主体、管理员、服务内容、域名和接入服务商信息。
3. 按页面要求完成管理员人脸或短信核验，企业主体补充法人或授权材料。
4. 提交接入服务商初审。资料被退回时，根据退回原因修改后重新提交。
5. 通过接入服务商初审后，等待通信管理部门审核。审核周期以当前页面提示为准，产品文档和对外承诺不应使用固定审核时长。
6. 取得备案号后，按平台要求在对应页面或协议页展示，并保留备案截图和回执。

备案失败的常见原因包括主体名称不一致、域名持有人不一致、服务类目与实际功能不匹配，以及联系人无法完成核验。域名、公众号和小程序主体应在项目开始阶段统一规划。

## 四、域名、HTTPS 证书与部署方式

### 1. 最小可行版本（MVP）与正式生产环境

本文中的 MVP 是“最小可行版本”，用于验证核心功能和审核流程。Cloudflare Tunnel 适用于 MVP、内网联调、演示环境和审核前的链路验证。Tunnel 可为本地或内网服务提供公网访问入口，但不应作为正式生产环境的默认架构。

正式生产环境应使用云厂商或机房提供的生产服务器，并至少具备以下条件：

- 独立的生产服务器或容器集群，和开发、测试环境隔离。
- 正式域名解析到公网 IP、负载均衡或 API 网关。
- 在 Nginx、Caddy、Ingress 或云负载均衡上终止 HTTPS，并配置自动续期。
- 防火墙和安全组仅开放必要端口，数据库、缓存等内网服务不得直接暴露公网。
- 日志、监控、备份、告警、发布回滚和密钥管理。

生产环境的典型链路是：

```text
小程序
  ↓ https://api.example.com
生产域名
  ↓
负载均衡 / Nginx / API 网关
  ↓
生产服务器或容器集群
  ↓
API 服务 + 数据库（内网）
```

在最小 MVP 或审核联调阶段，后端可运行在本地电脑、家用服务器或无公网入口的机器上，并通过 Cloudflare Tunnel 暴露服务：

```text
wx.request()
  ↓ https://api.example.com
微信网络层
  ↓
Cloudflare 边缘节点
  ↓ Cloudflare Tunnel
cloudflared
  ↓ http://127.0.0.1:8080
本地或内网 API 服务
```

Tunnel 仅解决服务的公网访问问题，不能替代生产服务器、小程序备案、合法域名配置、数据合规和账号审核。主要用户位于中国大陆时，应在实际网络环境中验证访问稳定性，并确认业务和域名符合相关合规要求。

### 2. 域名和证书

1. 在腾讯云等注册商购买自有域名。促销期可能存在约 10 元的首年价格，续费价格以购买页面为准。
2. 将域名 DNS 托管到 Cloudflare，添加 `api.example.com` 这样的业务子域名。
3. 对外访问必须使用 `https://`。微信不接受自签名证书、过期证书、证书域名不匹配或只支持过时 TLS 协议的服务。
4. MVP 使用 Tunnel 时，微信访问的是 Cloudflare 边缘节点提供的公开证书，内网服务可继续监听 HTTP。正式生产环境应在生产服务器、负载均衡或网关上安装受信任的公网证书并配置自动续期。
5. 证书覆盖的域名必须和小程序请求的域名一致。`api.example.com` 和 `www.example.com` 要分别配置，不能指望证书或白名单自动互相匹配。

### 3. MVP 操作流程：安装并运行 Cloudflare Tunnel

以下流程适用于本地服务、内网服务和审核联调。示例假设后端 API 在本机 `8080` 端口运行，业务域名为 `api.example.com`。正式生产环境应将后端部署至生产服务器或生产容器集群。

#### 第一步：安装 `cloudflared`

根据运行环境选择一种安装方式：

**macOS（Homebrew）**

```bash
brew install cloudflare/cloudflare/cloudflared
cloudflared --version
```

**Ubuntu / Debian**

```bash
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg \
  | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo 'deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main' \
  | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt-get update
sudo apt-get install cloudflared
cloudflared --version
```

**Windows**

使用 `winget` 安装：

```powershell
winget install --id Cloudflare.cloudflared
cloudflared --version
```

系统未提供对应的包管理器时，可从 [Cloudflare 官方下载页](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) 下载对应平台的安装包。

#### 第二步：登录 Cloudflare

执行以下命令：

```bash
cloudflared tunnel login
```

执行命令后，系统会打开浏览器。登录 Cloudflare 账号，选择目标域名，并授权 `cloudflared` 管理隧道。授权完成后，终端会提示证书文件的保存位置。

#### 第三步：创建隧道

```bash
cloudflared tunnel create miniapp-api
```

命令执行成功后会返回一个隧道 UUID，并在 `~/.cloudflared/` 目录生成凭据文件。请记录返回的 UUID，后续配置文件会使用该值。

查看隧道列表：

```bash
cloudflared tunnel list
```

#### 第四步：创建配置文件

创建文件 `~/.cloudflared/config.yml`，将 `<tunnel-id>` 替换为第三步返回的隧道 UUID，并将凭据路径改为实际文件路径：

```yaml
tunnel: <tunnel-id>
credentials-file: /Users/you/.cloudflared/<tunnel-id>.json

ingress:
  - hostname: api.example.com
    service: http://127.0.0.1:8080
  - service: http_status:404
```

Linux 配置示例：

```yaml
credentials-file: /home/用户名/.cloudflared/<tunnel-id>.json
```

Windows 配置示例：

```yaml
credentials-file: C:\\Users\\用户名\\.cloudflared\\<tunnel-id>.json
```

配置项说明：

| 配置项 | 作用 |
| --- | --- |
| `tunnel` | 要运行的隧道 UUID |
| `credentials-file` | 创建隧道时生成的凭据文件 |
| `hostname` | 对外提供服务的完整域名 |
| `service` | 内部 API 服务地址 |
| `http_status:404` | 未匹配到域名时返回 404 |

#### 第五步：将域名绑定到隧道

确保域名已经托管到当前 Cloudflare 账号后，执行：

```bash
cloudflared tunnel route dns miniapp-api api.example.com
```

该命令会在 Cloudflare DNS 中创建指向隧道的记录。检查 DNS 配置时，应能看到 `api.example.com` 已关联到对应的 Tunnel。

#### 第六步：启动隧道

启动隧道前，确认本地 API 正常运行：

```bash
curl http://127.0.0.1:8080/health
```

然后启动隧道：

```bash
cloudflared tunnel run miniapp-api
```

终端持续显示连接状态时，表示隧道已经建立。随后通过公网访问：

```bash
curl -I https://api.example.com/health
```

返回 `200` 或业务接口预期的状态码，表示“域名 → Cloudflare → Tunnel → 本地 API”的链路已经连通。

#### 第七步：配置后台服务

执行 `cloudflared tunnel run` 时，关闭终端会导致隧道停止。MVP 环境可使用系统服务保持运行；一次性联调可保持当前终端窗口处于运行状态。

**Linux**

Linux 的系统服务默认读取 `/etc/cloudflared/config.yml`。复制配置文件和凭据文件：

```bash
sudo mkdir -p /etc/cloudflared
sudo cp ~/.cloudflared/config.yml /etc/cloudflared/config.yml
sudo cp ~/.cloudflared/<tunnel-id>.json /etc/cloudflared/<tunnel-id>.json
```

然后将 `/etc/cloudflared/config.yml` 中的凭据路径改为：

```yaml
credentials-file: /etc/cloudflared/<tunnel-id>.json
```

安装并启动系统服务：

```bash
sudo cloudflared service install
sudo systemctl enable --now cloudflared
sudo systemctl status cloudflared
```

**macOS**

macOS 使用 `launchd` 管理后台服务：

```bash
sudo cloudflared service install
pgrep -fl cloudflared
```

服务未运行时，可停止已安装的服务并重新安装：

```bash
sudo cloudflared service uninstall
sudo cloudflared service install
```

**Windows（管理员 PowerShell）**

```powershell
cloudflared service install
Get-Service cloudflared
Start-Service cloudflared
```

服务模式运行前，请确认配置文件和凭据文件路径正确，并确保服务运行账户具有读取凭据文件的权限。

正式生产环境应使用生产服务器、网关或负载均衡承载业务流量，并配置发布、监控、备份和回滚流程。本地电脑不得作为正式生产服务的唯一运行节点。

#### 故障排查

| 现象 | 检查项 |
| --- | --- |
| `cloudflared: command not found` | 是否完成安装，终端是否重新打开，PATH 是否包含安装目录 |
| 隧道启动后立即退出 | `config.yml` 缩进、隧道 UUID、凭据文件路径和文件权限 |
| 域名无法访问 | DNS 是否托管到正确账号，是否执行 `tunnel route dns` |
| 返回 502 | 本地 API 是否监听 `127.0.0.1:8080`，端口是否填写正确 |
| 微信请求失败 | 是否配置服务器合法域名，是否使用 `https://api.example.com`，证书是否有效 |

### 4. 配置微信合法域名

进入微信公众平台的“开发 → 开发管理 → 开发设置 → 服务器域名”，根据实际使用能力填写：

- `request 合法域名`：`wx.request`、登录和业务 API。
- `socket 合法域名`：WebSocket 地址。
- `uploadFile 合法域名`：图片、视频或文件上传地址。
- `downloadFile 合法域名`：文件、图片或导出结果下载地址。
- `业务域名`：需要在小程序 WebView 中打开的网页地址。

配置时仅填写域名，例如 `https://api.example.com`。不得填写接口路径、查询参数、`localhost`、内网 IP 或临时穿透地址。代码请求的主机名、证书覆盖的主机名和后台白名单必须完全一致。

开发阶段可在开发者工具中临时勾选“不校验合法域名、TLS 版本以及 HTTPS 证书”。该选项仅用于本地调试，不能用于体验版或正式版部署。

## 五、上架前的审核准备

### 1. 确保审核流程可访问

审核员无法访问需要登录、邀请码、组织权限或白名单的页面。产品存在此类限制时，提交审核必须提供可用的测试路径：

- 在“体验成员”中加入审核用微信，或提供可直接登录的测试账号。
- 在审核备注中明确列出账号、密码、验证码获取方式、登录入口和测试步骤。
- 需要短信验证码时，提供固定测试号码、测试验证码或审核期间可用的接收方式。
- 需要管理员下发账号时，提前创建权限完整且数据已脱敏的测试账号。
- 必须绑定组织、邀请关系或设备时，提供审核账号对应的组织和操作说明。

审核账号应能够打开首页、核心功能、个人中心、退出登录和隐私协议页面。测试账号不能仅显示空白首页。

### 2. 准备小程序介绍和截图

在版本提审页面按当前页面要求填写并上传：

- 小程序名称、头像、简介、服务类目和客服电话。
- 首页截图，以及用于说明基本功能的核心页面截图。
- 登录后页面、数据列表、详情页、提交结果页等关键链路截图。
- 需要特殊权限时，说明权限用途和用户可获得的功能。

截图必须与当前提交版本一致，不得使用设计稿、浏览器页面或无法在小程序内复现的图片。截图中不得出现测试域名、调试面板、内部工号、真实手机号或其他敏感数据。

### 3. 填写隐私协议和用户隐私保护指引

在公众平台的隐私相关设置中，按实际采集情况填写：

- 收集哪些信息：手机号、头像昵称、定位、相册、设备信息、文件内容等。
- 为什么收集：注册登录、订单履约、客服、风控或功能实现。
- 信息如何使用、保存、删除，以及用户如何查询、更正和注销。
- 使用了哪些第三方 SDK，它们可能读取哪些数据。
- 客服、隐私负责人和用户反馈联系方式。

小程序首次需要隐私信息前，应展示隐私协议并取得用户同意。用户拒绝后，仍应允许访问不依赖该信息的公开页面。隐私协议中的采集项、代码实际申请的权限和审核截图必须一致，不得使用与产品实际情况不符的模板。

### 4. 提交审核

1. 在微信开发者工具中上传一个递增版本号。
2. 在公众平台的“版本管理”中确认版本、页面路径和版本描述。
3. 填写测试账号、审核备注、功能说明和隐私相关信息。
4. 提交审核后，保留版本号、提交时间和审核记录。
5. 审核通过后，点击“发布”。审核通过不等于版本已经对所有用户生效，发布操作仍需要管理员确认。

## 六、常见驳回点与处理方式

| 驳回现象 | 优先检查 |
| --- | --- |
| 无法登录或无法进入核心页面 | 测试账号是否过期、验证码是否可用、是否漏写登录步骤 |
| 请求失败或页面空白 | HTTPS 证书、服务器域名白名单、接口是否返回 200、Tunnel 是否在线 |
| 隐私问题 | 首次采集前是否同意、隐私协议是否写全、SDK 和代码采集项是否一致 |
| 类目不匹配 | 小程序实际功能、简介、服务类目和截图是否一致 |
| 功能无法体验 | 是否依赖内部组织、邀请码、付款或人工下发权限；审核备注是否给出替代路径 |
| 页面仍是测试状态 | 是否移除调试文案、测试账号提示、假数据和开发环境地址 |

## 七、提交前一页清单

- [ ] 小程序主体、域名主体和备案信息一致。
- [ ] AppID、生产接口地址和版本号正确。
- [ ] 所有请求、上传、下载和 WebSocket 域名都已配置合法域名。
- [ ] 正式生产环境使用生产服务器、网关或负载均衡；Cloudflare Tunnel 仅作为 MVP 或审核联调方案。
- [ ] 真机能完成注册、登录、核心业务、退出和异常重试。
- [ ] 审核账号可用，审核员不需要临时找开发人员开权限。
- [ ] 小程序介绍、基本功能截图和提交版本一致。
- [ ] 隐私协议、用户协议、权限弹窗和第三方 SDK 说明已填写。
- [ ] 测试数据已脱敏，日志、调试开关和内部地址已移除。

提交审核前完成以上清单，可减少因材料缺失或功能不可用导致的重复修改。
