# 原生微信小程序基本开发与面试

## 解决什么问题

原生小程序使用 WXML、WXSS、JavaScript 和 JSON 开发微信内业务，重点是页面、组件、数据更新和平台能力。上架流程不能替代开发基础；Uni-App 知识也不能直接替代原生 API 使用。

## 基本使用：一个计数页面

在开发者工具中新建原生项目，在 `app.json` 的 pages 注册 `pages/index/index`，建立对应文件。

```xml
<!-- index.wxml -->
<view>计数：{{count}}</view>
<button bindtap="increment">增加</button>
```

```js
// index.js
Page({
  data: { count: 0 },
  increment() {
    this.setData({ count: this.data.count + 1 })
  }
})
```

直接改 `this.data.count` 不会自动完成视图更新；使用 `setData` 提交必要变化。传输数据需可序列化，减少无意义的大对象、频繁全量列表更新。

## 页面、组件与路由

| 能力 | 基本用法 | 需要掌握的边界 |
|---|---|---|
| 应用 | App、app.json | 全局状态、启动参数、权限配置 |
| 页面 | Page、onLoad/onShow/onHide/onUnload | 首次加载与每次显示不同；退出清理定时器和请求 |
| 组件 | Component、properties、triggerEvent | 属性下行、事件上行；behavior 按需复用 |
| 事件 | bindtap / catchtap | catch 阻止冒泡；dataset 获取业务标识 |
| 路由 | navigateTo、redirectTo、switchTab、reLaunch | 页面栈与 tabBar 规则不同 |
| 请求与存储 | wx.request、存储 API | HTTPS 合法域名、超时、大小限制和账号隔离 |
| 分包 | subpackages 与按需加载 | 包限制和基础库能力以当前平台规定为准 |

## 常见场景：登录、上传与支付

`wx.login` 返回临时 code，由服务端调用平台接口换取身份和会话相关信息，再签发业务会话。openid 标识用户在对应应用的身份，不能把客户端上传的 openid 直接当作可信登录证据；session_key 与应用密钥在服务端保护。

上传使用上传域名和服务端类型/大小校验；相册、相机、位置等按业务需要和平台规范授权，处理拒绝与隐私要求。支付由服务端创建交易并验签处理异步通知，客户端结果需要服务端确认，参考 [登录与支付链路](/doc/uniapp/页面开发登录与支付基本实践)。

## 再深入：性能与平台边界

视图层与逻辑层通信有成本，优化先看 setData 频次、数据量、渲染节点和图片尺寸，而不是先背底层架构。用工具和真机观察时间线，优先更新具体字段、按需加载和分页；插件、WebView、不同渲染模式的能力边界按平台实际选择复核。

## 面试递进与验收

| 基础题 | 场景追问 | 深入要点 |
|---|---|---|
| setData 怎么用？ | 长列表为什么卡？ | 跨层通信、差量更新、节点规模 |
| onLoad/onShow 区别？ | 从详情返回是否刷新？ | 页面栈、状态保留、刷新标记 |
| wx.login 怎么登录？ | code 过期、会话失效怎么办？ | 服务端身份校验和会话生命周期 |
| 分包怎么配置？ | 首屏与进入分包的体验如何平衡？ | 按需加载、预下载与资源策略 |
| 如何上线？ | 开发工具正常但真机失败？ | 域名、权限、基础库、隐私和审核路径 |

至少验证真机、拒绝权限、弱网、登录失效、重复提交和返回刷新，再阅读 [部署与上架审核](/doc/微信小程序/微信小程序快速部署与上架审核)。
