# 性能优化与多端避坑全景指南

## 使用入口：先解决问题，再做验证

改善多端加载与交互并处理平台差异。

**先做基本操作**：先在目标真机测包体积、加载、列表与 setData 数据量，复现差异后再优化。初次学习可先完成[本模块基础实践](/doc/uniapp/页面开发登录与支付基本实践)。

**再逐步深入**：基本 API 与输入输出 → 常见失败和使用边界 → 场景排查与优化 → 本文机制分析与源码。面试先讲用途和自己的操作过程，再回答场景与原理追问。

跨端开发最怕“一处编写，处处调 Bug”。在享受 Uni-App 高效开发的同时，各端底层宿主（尤其是微信小程序与手机原生 WebView）在性能底线、包体积限制、安全区适配以及系统 API 上存在天然壁垒。

本文提炼一线大厂在 Uni-App 生产环境中必须踩透的**性能调优手段**与**全平台避坑指南**。

## 一、 性能调优：突破双线程通信瓶颈

### 1. 根治 `setData` 频繁调用导致的卡顿掉帧

由于双线程模型下，**逻辑层向视图层发送数据必须经过 JSON 序列化并跨线程排队**：
* ❌ **反模式 1：把页面无需渲染的纯业务变量放在 `ref` / `reactive` 中。**  
  * 例如：轮询定时器 `timer`、当前页码 `pageIndex`、网络请求状态控制器。如果它们被定义在响应式对象中，每次赋值都会触发底层的跨线程 Diff 检查。
  * ✅ **解法**：界面不展示的数据，定义为普通 JS 变量（`let pageIndex = 1;`）或非响应式对象。

* ❌ **反模式 2：长列表局部修改却直接整体重新赋值。**  
  * 列表有 100 条数据，用户点赞了第 50 条，如果直接执行 `list.value = [...newList]`，底层会将整整 100 条数据打包重新序列化一次，产生几十 KB 的通信负载。
  * ✅ **解法**：精准修改路径更新或使用支持局部 Patch 的深层属性修改。

* ❌ **反模式 3：在 `onPageScroll` 滚动监听中无脑执行 `setData`。**  
  * 屏幕快速滑动时，`onPageScroll` 每秒触发高达几十次。如果在里面直接修改响应式数据，会导致通信信道彻底拥堵，页面直接出现白屏或剧烈跳动。
  * ✅ **解法**：滚动监听必须配合**节流（throttle）**或直接改用 CSS `position: sticky` 实现吸顶，绝不要靠 JS 监听去算坐标做悬浮。

## 二、 突破小程序 2MB 单包体积限制

微信小程序对主包大小有严格的 **2MB 限制**（分包总和不超过 20MB）。一旦超过 2MB，微信开发者工具将直接拒绝上传提审。

### 1. 瘦身四步法则

```text
               ┌── 1. 静态资源 CDN 化 ───► 将 static/ 目录下的所有音频、背景大图移至云存储
               │
2MB 瘦身核心链路 ┼── 2. 业务功能全面分包 ─► 主包仅保留 TabBar 核心页，其余全部入 subPackages
               │
               ├── 3. 字体图标按需裁剪 ─► 严禁引入几十 MB 的 TTF 字体，改用 SVG 或在线字体
               │
               └── 4. 开启分包预加载 ───► 用户进入主包页面后后台静默下载，抹平分包卡顿
```

### 2. 实战：`pages.json` 分包与预加载配置

```json
{
  "pages": [
    // 主包：必须极度精简，通常只放 3~5 个 TabBar 页面和冷启动 Loading 页
    { "path": "pages/index/index" },
    { "path": "pages/category/category" },
    { "path": "pages/mine/mine" }
  ],
  "subPackages": [
    // 分包 1：商品与营销业务
    {
      "root": "packageGoods",
      "pages": [
        { "path": "detail/detail" },
        { "path": "search/search" }
      ]
    },
    // 分包 2：个人中心深层设置、关于我们、意见反馈
    {
      "root": "packageUser",
      "pages": [
        { "path": "setting/setting" },
        { "path": "address/list" }
      ]
    }
  ],
  // 分包预下载：当用户停留在首页时，由系统在后台空闲时悄悄拉取 packageGoods
  "preloadRule": {
    "pages/index/index": {
      "network": "all",
      "packages": ["packageGoods"]
    }
  }
}
```

## 三、 多端屏幕适配与异形屏安全区全解

### 1. `rpx` 响应式原理与使用戒律
* **基准定义**：无论屏幕真实物理像素多大，屏幕宽度永远等于 **`750rpx`**。
* **计算逻辑**：
  $$\text{真实像素} = \text{设计稿标注值} \times \left(\frac{\text{屏幕实际宽度}}{750}\right)$$
* ⚠️ **使用戒律**：
  * **字号尽量用 `px` 或固定值**：在极大屏幕（如 iPad 或折叠屏大屏展开）上，如果文字字号盲目用 `rpx`，字会被放大得像老年机一样失真，推荐使用 `clamp()` 或在平板模式下锁死最大宽度。
  * **边框线（1px）严禁使用 `rpx`**：在部分低 DPI 的安卓机上，`1rpx` 经数学计算后可能小于 0.5px，导致边框直接消失看不见！**边框务必直接写 `1px solid #eee`**。

### 2. 异形屏与底部“小黑条”安全区（Home Indicator）适配

全面屏手机（iPhone X 及以上、各类全面屏安卓机）底部带有滑动横条，如果你的吸底按钮（如“立即支付”）贴死底部，会导致用户误触甚至无法点击。

#### ✅ CSS 纯样式安全区方案（推荐）
```css
.fixed-bottom-bar {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
  height: 100rpx;
  background-color: #ffffff;

  /* 核心：内边距向下自动撑开系统安全区域 */
  padding-bottom: constant(safe-area-inset-bottom); /* 兼容 iOS < 11.2 */
  padding-bottom: env(safe-area-inset-bottom);      /* 兼容 iOS >= 11.2 与现代安卓 */
  box-sizing: content-box;
}
```

## 四、 跨端开发踩坑与防暴雷手册

### 坑 1：怎么在没有 DOM 的环境获取节点宽高与位置？
* ❌ 严禁：`document.querySelector('.my-box').getBoundingClientRect()`
* ✅ 正确做法：使用 `uni.createSelectorQuery()`
```ts
import { onMounted } from 'vue';

onMounted(() => {
  const query = uni.createSelectorQuery();
  // 注意：如果在自定义组件内，必须写 query.in(this)
  query.select('.my-box').boundingClientRect((data) => {
    if (data) {
      console.log('节点宽度:', data.width);
      console.log('距离视口顶部:', data.top);
    }
  }).exec();
});
```

### 坑 2：微信小程序端特有的“用户隐私保护协议”
* **现象**：在微信小程序中直接调用 `uni.chooseImage`、`uni.getLocation` 或剪贴板，接口静默失败或直接报错。
* **原因**：微信自 2023 年底起强制要求：**在调用隐私权限前，必须先弹出微信官方规范的《用户隐私保护指引》授权弹窗，经用户主动点击同意后才放行**。
* **解决**：在项目中统一封装 `PrivacyPopup` 全局隐私授权弹窗组件，监听 `wx.onNeedPrivacyAuthorization` 事件。

### 坑 3：H5 端本地开发跨域（CORS）与部署刷新 404
* **跨域**：仅在 H5 浏览器端存在，小程序和 App 走的是底层原生网络栈，无 CORS 限制。
  * 在 `vite.config.ts` 中配置代理服务器：
    ```ts
    server: {
      proxy: {
        '/api': {
          target: 'https://api.example.com',
          changeOrigin: true,
          rewrite: (path) => path.replace(/^\/api/, '')
        }
      }
    }
    ```
* **页面刷新 404**：H5 端如果开启了 `mode: 'history'`，在 Nginx 部署时必须添加重定向回退：
  ```nginx
  location / {
    try_files $uri $uri/ /index.html;
  }
  ```

### 坑 4：图片标签路径大小写与格式
* 在 Windows 电脑上开发，图片路径大小写不敏感（`/static/logo.PNG` 与 `logo.png` 都能正常显示）。
* **一旦打包到 iOS 真机或 Linux 服务器，路径严格区分大小写**，大小写不符会导致图片直接破损缺失。统一规定：所有静态资源文件与文件夹**全部小写+中划线命名**。
